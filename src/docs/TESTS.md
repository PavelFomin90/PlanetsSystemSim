## 8. Тестируемость
1. **Организация тестов**:
   - Создать директорию `tests/` в корне проекта
   - Размещать тесты по структуре, соответствующей src/: `tests/unit/`, `tests/integration/`
   - Для каждого файла в src/ создавать соответствующий тестовый файл с суффиксом `.test.ts`

2. **Выбор тестового фреймворка**:
   - Использовать Jest как основной фреймворк для тестирования
   - Jest хорошо поддерживает TypeScript и предоставляет встроенные моки и спайы

3. **Настройка тестовой среды**:
   - Добавить конфигурацию Jest в package.json или отдельный файл `jest.config.js`
   - Настроить транспиляцию TypeScript через `ts-jest`
   - Настроить мокирование для DOM элементов и Canvas API

4. **Тестирование юнитов**:
   - Писать юнит-тесты для всех классов и функций
   - Тестировать каждый метод класса с различными сценариями
   - Покрывать как позитивные, так и негативные сценарии
   - Для класса Dot тестировать методы move(), accelerate(), computeGravityForce()
   - Для класса Vector тестировать методы addVector(), toDecartCoords(), toPolarCoords()


5. **Тестирование взаимодействий**:
   - Писать интеграционные тесты для взаимодействия между компонентами
   - Тестировать взаимодействие System с Dot
   - Тестировать взаимодействие Drawer с Canvas контекстом
   - Тестировать взаимодействие TranslateController с событиями

6. **Мокирование зависимостей**:
   - Мокировать CanvasRenderingContext2D в тестах
   - Мокировать DOM элементы и события
   - Использовать моки для таймеров (setTimeout, setInterval)


7. **Тестирование асинхронного кода**:
   - Использовать async/await для тестирования асинхронных операций
   - Тестировать методы, использующие requestAnimationFrame
   - Проверять корректность работы с промисами и коллбэками

8. **Покрытие кода**:
   - Настроить инструменты для измерения покрытия кода (istanbul)
   - Стремиться к покрытию не менее 80% для ключевых модулей
   - Фокусироваться на покрытии бизнес-логики

9. **Написание читаемых тестов**:
   - Использовать describe/it блоки для структурирования тестов
   - Писать понятные названия тестов, описывающие поведение
   - Использовать Given-When-Then или Arrange-Act-Assert паттерн

10. **Тестирование производительности**:
    - Добавить бенчмарки для вычислительно интенсивных методов
    - Тестировать производительность computeGravityForcesVector при большом количестве тел
    - Мониторить регрессию производительности

11. **CI/CD интеграция**:
    - Настроить запуск тестов в GitHub Actions
    - Добавить проверку покрытия кода
    - Запускать тесты при каждом коммите и pull request

12. **Документирование тестов**:
    - Писать комментарии для сложных тестовых сценариев
    - Поддерживать актуальность тестов при изменении кода
    - Документировать сложные моки и заглушки

Эти правила обеспечат создание надежной и поддерживаемой тестовой базы для проекта, что повысит качество кода и упростит дальнейшую разработку.
