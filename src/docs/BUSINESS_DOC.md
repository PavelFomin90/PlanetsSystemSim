# Business-документация: PlanetsSystemSim

Данный документ описывает бизнесовую и техническую составляющую проекта `PlanetsSystemSim` — симулятора гравитационной системы тел, реализованного на TypeScript и Canvas.

## 1. Бизнес-часть

### Текущий бизнес-функционал

Система предоставляет пользователю возможность визуализировать и исследовать динамическое поведение тел (планет, звёзд, спутников) в замкнутой гравитационной системе. Основная цель — создание интерактивного образовательного или демонстрационного инструмента для изучения физических законов движения и взаимодействия тел.

**Ключевые возможности для пользователя**:

- **Интерактивная визуализация**:
  - Отображение тел в виде окружностей на 2D-холсте.
  - Отрисовка траекторий (орбит) движения тел.
  - Генерация фоновых звёзд для улучшения визуального восприятия.

- **Физическая симуляция**:
  - Расчёт гравитационного взаимодействия между телами.
  - Обновление скорости и положения тел на основе ускорения.
  - Поддержка тел с различной массой, цветом и начальными параметрами.

- **Управление камерой**:
  - Перемещение по полю (перетаскивание мышью, стрелки на клавиатуре).
  - Масштабирование (колесо мыши, клавиши `W`/`Q`).
  - Сброс масштаба (клавиша `R`).
  - Отслеживание выбранного тела (камера следует за объектом).

- **API для инициализации**:
  - Программное создание тел (`Dot`) с заданием массы, координат, скорости и цвета.
  - Добавление тел в систему (`System`).
  - Настройка отрисовки (`Drawer`) и управления (`TranslateController`).
  - Запуск анимации через `requestAnimationFrame`.

Проект ориентирован на разработчиков и преподавателей, которые хотят продемонстрировать поведение гравитационных систем без необходимости писать физический движок с нуля.

## 2. Техническая часть

### Текущее техническое состояние

Проект построен с использованием современных практик разработки и соответствует стандартам чистого кода и поддерживаемой архитектуры.

**Стек технологий**:
- Язык: TypeScript
- Платформа: браузер (Canvas API)
- Сборка: Webpack
- Стиль: ES6+ с ООП

**Архитектура**:
- Модульная структура: разделение на `models`, `controller`, `utils`.
- Принцип единственной ответственности (SRP): каждый класс решает одну задачу.
- Использование паттернов: Singleton (`TranslateController`, `Tracker`), инверсия зависимостей.
- Чёткое разделение: модель (физика), вид (отрисовка), контроллер (управление).

**Основные модули**:
- `Dot` — физическое тело с массой, скоростью, ускорением.
- `System` — контейнер для управления коллекцией тел.
- `Drawer` — отрисовка на Canvas (тела, орбиты, фон).
- `Tracker` — отслеживание выбранного тела камерой.
- `TranslateController` — управление масштабом и позицией холста.

**Типизация и качество кода**:
- Полная типизация через TypeScript.
- Интерфейсы с префиксом `I` (`IDot`, `ICoords` и т.д.).
- Аннотации JSDoc для всех публичных элементов.
- Соглашения об именовании: camelCase, PascalCase, `const`/`let`.

**Производительность**:
- Анимация на `requestAnimationFrame`.
- Физика обновляется каждые 30 мс через `setInterval`.
- Ограничение истории координат (орбит) до 500 точек.
- Троттлинг обработчиков мыши (20 мс) для оптимизации.

**Обработка ошибок**:
- Проверка существования `canvas` и `context`.
- Возврат `undefined` или `null` в случае ошибок.
- Использование `throw` при критических ошибках (например, отсутствие 2D-контекста).
- Отсутствие централизованного обработчика ошибок.

**Тестирование**:
- На текущий момент тесты отсутствуют.
- В `CODING_RULES.md` есть рекомендации по вводу Jest, мокированию Canvas и настройке CI/CD.
